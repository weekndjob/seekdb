## 内核修改与不变量

1. **默认参数直接准备。** 原 TOKENIZE 每次先生成默认 JSON，再解析回同一组配置，产生重复 JSON 构建、解析和临时分配。新 `ObFTParseHelper::init_default` 直接使用规范的内建默认值，仍通过原解析器描述符设置过滤、大小写及归并标志。仅无第三参数的 TOKENIZE 使用该路径；自定义 JSON、ALL 输出、非法选项及其错误路径保持原处理。逐次求值真实文本与解析器，没有缓存分词结果或跨会话参数。
2. **临时内存生命周期。** TokenizeParam 借用外层 TempAllocGuard 的分配器，不再为配置建立独立 arena，同时移除未使用的临时 arena。嵌套 guard 在外层使用期间不会重置该内存；配置、分词与结果打包都在该作用域内完成。没有把临时指针保存到全局或执行结束后的对象中。
3. **BENG 稳定结果缓冲。** 规范化直接写入调用方拥有的内存，移除每词第二次分配和复制。结果在流推进和解析器销毁后仍有效；其他分析器默认保持原有内部缓冲复用。没有改变大小写、过滤、频次或排序规则。
4. **字典构建碰撞检查。** 第一次候选仍按原序为所有子节点编码；其后候选发现一个占用位置即可拒绝该候选，停止无效扫描。编码、最终位置和词典匹配规则保持不变。

5. **小路数归并直接分派。** 运行栈采样中的 35 个查询样本有 17 个落在 DaaT 归并链路。采样受调试器干扰，只作热点线索，不解释为精确 CPU 占比。原初始化对不超过三路输入已经选择 ObSRSimpleMerger；本次仅在该条件下限定调用同一实现，允许内联 push/top/pop/empty/相等标记操作，减少逐行间接分派。三路以上仍使用原多态路径；同一份算法主体保留原比较、按迭代器序号处理相同 ID、分数收集顺序和错误传播，没有跳过候选文档。新增一到五路的带权并集、共享/独立 ID、提前耗尽和反复读取结束测试。

此前已验证的 IK 解码、生命周期、词频表独占锁及检索热路径改动保留。固定 IK 处理器/ASCII 实验以及快速 DDL 重试实验都未证明足够的整体构建收益，已撤回。快速重试虽然确实缩短了 DAG 重试间隔，但构建类别两组分别退化约 4.15% 和 4.37%，因此没有保留该调度器改动；也未将那项假设写成零分的已证实根因。中间 BENG、BENG+DAT 和 DDL 实验记录均留档。仅增加默认参数改动的完整对照也未过性能门槛，两组综合分别为 −4.83% 和 −6.55%，没有推送；最终候选在此基础上增加上述归并优化，必须以最终完整对照而非默认参数的局部假设验收。
