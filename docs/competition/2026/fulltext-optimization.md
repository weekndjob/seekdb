# 全文索引调优

官方题面：[全文索引性能优化](https://oceanbase.yuque.com/org-wiki-obtech-vh7w9r/hc3pio/za7cfo5cazcrihhq)。

## 本次修复依据

用户最近反馈的平台日志显示执行成功，但综合提升率为 −23.7538%，成绩仍为 0。日志未给出完整提交 SHA。本次以此前已推送的 `3b65a4a3bac92bc6c50c9d9a00c95ab72444bf37` 二进制作为本机对照。执行成功只说明评测运行完成；负提升率会被评分公式截断为零，不能据此认定性能要求已经通过。

本次保留该版本二进制，在同一台机器、相同 Release 配置和隔离实例中进行完整配对测试。未使用仓库内较旧的固定基线宣称官方成绩。平台未提供本轮固定基线的更多明细。

索引构建栈采样命中字典范围查找中的重复字符集查找和间接比较。源码 `ob_strnncoll_mb_bin` 在非前缀模式下执行字节比较和长度比较，与 `ObString::compare` 的顺序一致，因而可以省去重复派发。采样仅用于定位路径，不解释为精确 CPU 占比。

另一个改动涉及词频归并表。全源码检索和调用链核查确认，五处实例均为函数内局部表，供同步分词、查询分词或索引行生成使用；调用返回前复制结果，不跨线程共享。原表仍为每次插入、查找、节点分配和释放加锁。

## 内核改动及不变量

- 字典范围边界改用等价字节比较。保持原有遍历顺序和重叠范围的首次匹配规则，没有引入新的排序假设。
- 词频表及其独占节点分配器使用 `NoPthreadDefendMode`。优化器、当前检索路径和兼容检索路径统一使用该别名。共享字典、缓存和全局分配器的锁未改。
- 保留原有哈希、排序规则、等价词判断、首次频次为 1、后续频次累加及最后键表示。没有改变分词、停用词、BM25、BOOLEAN、排序或 LIMIT 规则。

此前已提交的分配器生命周期、仲裁、字符解码和检索热路径改动继续保留。本次试验过的调度唤醒、DDL 提交后调度和字典压缩未证明稳定整体收益，均未包含在本次提交中。原始实验记录保存在工作区外部验证目录。

官方数据、SQL、测试参数、计时逻辑、评分脚本、固定基线和工作流未改。

## 正确性与构建验证

- 原生 Release 构建和 60 个 SQL 单元测试通过。新增覆盖 264 个字典边界探针（含 NUL、全部单字节值、中文、补充平面字符），以原字符集比较函数核对范围选择，并用词条集合核对命中。重叠范围也验证首次匹配。
- 四个线程分别处理 32 篇文档，每篇 40 次词频输入，覆盖哈希冲突、复用、独立计数和原有首次频次约定。
- 优化前后 334 项输出完全一致：320 个多语言、随机和长文本 TOKENIZE，以及 14 项完整命中 ID、分数、阈值、BOOLEAN、NOT MATCH、排序、LIMIT、OFFSET 和无命中结果。两个版本读取同一份物理索引。
- 额外四个真实 SQL 连接并发执行 128 个 TOKENIZE 和 4 个 MATCH 查询，前后输出完全一致。
- 原 `fts_index/tokenize_function.test` 通过。MariaDB 客户端临时副本只做结果展示格式兼容及同一错误码映射；仓库原测试与预期未改。
- 两个连接并发完成六次 IK/BENG 索引构建与删除，逐次核对全部 100 个命中 ID，并确认回滚行不进入结果。

源码与二进制来源：候选 SHA-256 `61ec96fef2fc84972e643e838b0cd6961c6333efcce7e8aaf79c28e0452b1152`；对照 SHA-256 `efea0268c1ca060013175584bf3a854b35455a644ab8f4eb1616c689a4bdcc7c`。源码清单逐文件核对 Windows 与实际构建输入，详见验证包。
